# R01–R03 手动测试清单

本次修改未运行自动化测试、浏览器测试或真实模型/采集调用。以下由你手动执行。

在单独的数据目录和端口启动，便于区分 ai-radar 与 intel-radar 的服务：

```bash
cd /Users/zhaomin/Projects/ai-radar
RADAR_DATA_DIR=/tmp/ai-radar-r01-r03-check python3 -m radar serve --port 8793
```

打开 <http://127.0.0.1:8793/setup>。模型与 TikHub 凭证仍读取 ai-radar 的 `.env`。若该测试服务已在运行，先在其终端按 Ctrl+C，再执行命令加载新代码。AI 相关性校验、目标理解与关键词生成会调用模型；只有点击“开始采集”才调用采集接口。

## 1. 目标合法性、概念理解与修改

| 输入 / 操作 | 应看到的结果 |
| --- | --- |
| 首次进入 | 保留三个问题，第二、第三问暂不可操作 |
| 输入“童装穿搭”，点击“校验 AI 相关性” | 在当前页提示非 AI 目标，后两问仍不可操作；不进入计划预览 |
| 分别输入“FDE”“AI视频”“AI搞钱”“AI宠物”“AI童装”并校验 | 直接通过并开放后两问，不要求确认缩写、选择子方向或补充关注维度 |
| 输入“研究 FDE 数值方程求解，与人工智能无关” | 尊重明确的非 AI 含义，不强行解释成 AI 岗位 |
| 输入未说明含义的内部行业代号 | 第一步不因含义未细化而要求澄清；关键词阶段确实无法确定主流含义时再提示补充 |
| 目标通过后修改第一问的任意内容 | 后两问再次锁定，要求重新校验 |

这些用例检查真实模型的语义质量；失败时记录输入和页面提示，不能仅凭程序能拦截某个返回状态判断模型理解正确。

## 2. 渠道差异与排除需求

1. 输入“AI 视频”，完成目标校验。
2. 选择“抖音”和“GitHub”（抖音需要已配置 TikHub Key）。
3. 第三问填：“关注 AI 短剧、视频生成、剪辑和配音工具，不看 AI 漫剧。”
4. 点击“生成计划预览”。等待期间停留在配置页；完成后进入预览。
5. 核对：抖音词偏内容形式和创作案例，GitHub 词偏开源工具和技术实现，关键词应提炼核心目标和关注方向，不要求原样保留“AI 视频”；扩展词按渠道适配，适用的短词可以相同；AI 漫剧不应成为正向关键词。排除范围应包含 AI 漫剧。
6. 点击“返回修改”，应保留三问答案和已通过的相关性校验。仅修改第三问无需再次校验相关性。
7. 另用 FDE 生成计划，预览的目标理解应采用 Forward Deployed Engineer，关键词围绕该岗位的主流 AI 实践，不混入数值计算解释；AI 搞钱应围绕 AI 工具、内容、产品或服务变现，不要求先选子方向。
8. 第三问改为“改成监控童装，与 AI 无关”，应在配置页要求澄清或修改需求，不能产生无关目标的计划。

补充关键词验收：第一问填“FDE”，第三问填“FDE成功案例、FDE创业经历”，选择抖音、X、GitHub。关键词应覆盖 FDE 相关关注方向，不要求首词为独立“FDE”；抖音应体现“FDE案例”“FDE创业”，X 使用中文扩展词，GitHub 可出现“FDE工具”等。不能出现“FDE 前沿部署工程师”等释义拼接词，也不能为渠道差异丢掉第三问的关注点。共享短词不应触发校验失败。

长句验收：第一问填“我想了解普通人如何利用AI制作视频赚钱”，第三问填“重点关注成功案例、变现方式和实操经验”。应提炼为“AI视频变现”“AI视频案例”“AI视频实操”等短词，不应由程序把完整原句重新插入搜索词。

## 3. 固定能力和参数

预览中每个渠道必须包含当前 `radar/capabilities.py` 的 `MENU` 中全部对应能力。当前固定规则：

| 渠道 | 应有任务与参数 |
| --- | --- |
| B站 | 每关键词 1 个 `bili_search`，7 天、1 页、click |
| YouTube | 每关键词 1 个 `youtube`，this_week、不限时长 |
| 抖音 | 每关键词同时有 `douyin` 和 `douyin_low_followers`，7 天，label 分别 0、1 |
| TikTok | 每关键词 1 个 `tiktok`，7 天 |
| 小红书 | 每关键词 1 个 `xhs`，固定接口参数 |
| X | 每关键词 1 个 `x`，2 天、1 页、Top |
| GitHub | 每关键词 1 个 `github_search`，7 天、pushed；另有 1 个 `github_trending`，daily |
| Hugging Face | 1 个 `hf`，limit=10，搜索词为空 |
| Hacker News | 1 个 `hn`，hours=36、min_points=0，搜索词为空 |
| 资讯 RSS | 1 个 `news`，hours=48，搜索词为空 |

每个任务最多保留 40 条，每渠道最多采用 4 个关键词，总任务最多 30 项。不应出现此前移除的 B站分区榜、热门、热搜及抖音热搜。只选择 HF/HN/RSS 时，依然可以生成计划，显示“无需搜索词”。

确认后点击“导出配置”，可直接检查任务 ID、`capability_id`、`query`、`options`、`channel_keywords`、`goal_interpretation` 等字段。抖音两个能力要成对使用完全相同的关键词；无关键词能力只出现一次。

## 4. 预算缩减与失败保护

Ctrl+C 停掉测试服务，以较小预算重新启动：

```bash
RADAR_DATA_DIR=/tmp/ai-radar-r01-r03-check TIKHUB_MAX_USD=0.09 python3 -m radar serve --port 8793
```

仅选择抖音，以较宽的 AI 视频目标生成计划。当 Agent 提供多个词时，应自动只采用Agent 排在首位的核心搜索词，并保留普通视频与低粉爆款两个任务，预算预留为 $0.06；页面说明关键词缩减。若模型本身只提供一个词，则不会显示缩减提示。

再以 `TIKHUB_MAX_USD=0.01` 重启，重新生成抖音计划：应在当前配置页提示最小计划超过预算，不能只启用一种抖音能力来绕过限制。此前已确认的配置保持有效。测试完去掉这个环境变量重启。

## 5. 预览、确认、重启与 R04/R05

- 生成预览后不确认，访问 `/plan`，原有效配置应保持不变；生成及确认均不会自动采集。
- 确认后配置版本改变，实际采集使用刚刚预览的冻结任务。
- 在相关性校验或关键词生成期间刷新网页，应恢复等待；若期间重启服务，应显示任务中断并允许重试，不能永久停在“生成中”。
- 若有旧配置，页面会标明是此前保存的计划；重新配置并确认后才采用新规则。
- 用 FDE 配置完成一次采集，在结果页检查 R04 相关性、原文证据、R05 分组与费用。导出的配置中 `monitoring_goal` 应与目标理解一致，`monitoring_scope` 应保留第一问和第三问的关注及排除范围；这些字段仍由原有路径传给 R04。
