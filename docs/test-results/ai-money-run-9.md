## 效果评估

### 1. 有主题线索，但“相关”判定偏宽

可以获得AI教辅绘图变现、AI视频副业、AI代理支付、AI SaaS计费和部署等线索。但抖音与X均被模型全部判相关，不代表100%准确。

明确问题样本：抖音“明年起贬值最狠的6样东西”仅带“AI搞钱”标签就被判相关；“AI时代，你的工作安全吗”也被放行。这违背“不能将关键词命中当作充分条件”的要求。应提高实质关联要求，缺少可见商业行为、项目或方法时标为不确定，而不是由标签推断。

### 2. R05过度合并，尚未达标

第一批将22条不同抖音内容整体归为“AI副业变现方法”；还将多个独立仓库归为“AI应用开发与变现模板”等宽泛组。第三批将10条不同YouTube内容合并为“AI副业与赚钱方法”。这些属于同类别，不足以认定同一个具体主题。

同时，最后跨批合并返回缺少成员字段，结构校验成功阻止了不完整结果发布，但说明接口契约与实际模型输出尚不稳定。需要先修复跨批输入输出契约，再加强具体对象一致性检查，优先保留独立单条。

### 3. 低成本候选筛选存在资源错配

40条抖音全站热搜没有一条被判相关，却全部占用了R04候选额度。与此同时17条GitHub内容尚未分析，其中包括明确描述“可部署并变现AI应用”的仓库。原因之一是热搜被当作独立source参与轮转，且程序未充分压低无关榜单候选优先级。应按用户选择的平台统一分配候选，降低泛榜单配额，并在预算允许时继续处理高相关候选。

### 4. 时间参数未真正生效

X任务标注7天，但查询词没有since占位符；现有适配器只替换存在的占位符，不自动附加日期，所以20条X内容中4条早于7天。GitHub搜索同样仅替换已有{d}，生成词未带日期约束，配置的14/30天没有应用。不能将GitHub仓库创建时间统一当作更新时效：应该明确监控新建仓库还是近期更新，再应用对应条件。

### 5. 文本证据有限，不能据此确认收益

抖音主要只有标题或描述截断，YouTube主要为标题和短摘要。内容中“日赚5000”等均为来源陈述，没有独立核实。当前适合提供待进一步阅读的线索，不能将这些陈述当作已证实收入。

### 6. 覆盖缺口

微信未接入；X的Latest搜索失败，错误没有足够响应信息判断是参数、权限还是上游服务问题，不能直接归因为某一个原因。需要补充脱敏诊断后确认。

## 修复优先级

1. 修复R05跨批成员契约与过度合并，保证完整、具体的主题归属。
2. 修复X/GitHub时间约束，使预览设置与实际请求一致。
3. 收紧R04实质相关性标准，避免标签驱动的误判。
4. 调整候选配额，减少全站热搜噪声，优先处理有商业内容的待处理条目。
5. 排查X失败原因；微信作为独立接入任务评估，不伪装成已支持平台。
